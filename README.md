# spec_driven_development

Набор спецификаций. Здесь лежат документы, которые фиксируют **как** принимается решение — до того, как написан код.

## Что это

Репозиторий спецификаций, а не кодовая база. Каждая спецификация описывает отдельный подход: что считаем результатом, по каким критериям проверяем, когда останавливаемся и что считаем провалом.

Спецификация здесь — рабочий инструмент, а не документация готового продукта. Её можно применить к новой задаче и получить вердикт, не начиная разработку.

## Структура

| Путь | Что внутри |
|---|---|
| `search_theory/SKILL.md` | Проверка бизнес-идеи, гипотезы или ниши на состоятельность: критерии денег, признаки незанятого места, проверка рычага, красные флаги и правила решения «браться или закрыть» |

## Формат

Спецификации хранятся как Agent Skill: файл `SKILL.md` в папке с именем скила, с frontmatter `name` и `description`. В таком виде файл подхватывается ассистентами, работающими с этим репозиторием.

Читать их можно и как обычный документ. В каждой спецификации есть назначение, когда применять и когда нет, обязательные входы, порядок работы, критерии и правила решения.

## Как добавить спецификацию

1. Создать папку с именем скила
2. Положить внутрь `SKILL.md` с frontmatter: `name` и `description`
3. Описать назначение, входы, порядок работы, критерии и правила решения
4. Добавить строку в таблицу структуры выше
