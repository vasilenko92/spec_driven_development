# Скилы

Переиспользуемые методы работы. Скил описывает **как** выполнять работу определённого типа и применим к любой задаче, а не к чему-то одному в этом репозитории.

## Формат

```
skills/
  <имя-скила>/
    SKILL.md
```

Имя папки совпадает с полем `name` во frontmatter.

`SKILL.md` начинается с frontmatter:

```yaml
---
name: имя-скила
description: Когда применять и что получается на выходе
---
```

`description` — не украшение. По этой строке ассистент решает, подхватывать скил или нет. Поэтому в ней должно быть понятно, **когда** скил применим и **какой результат** он даёт.

## Что должно быть внутри

| Раздел | Зачем |
|---|---|
| Назначение | Какой результат даёт скил |
| Когда применять и когда не применять | Отсекает ложные срабатывания |
| Обязательные входы | Что нужно знать до начала |
| Порядок работы | Шаги в порядке выполнения |
| Критерии | По чему принимается решение |
| Правила решения | Явные пороги, а не «оценить здраво» |
| Формат вывода | Что должно получиться на выходе |
| Обработка пробелов | Что делать при нехватке данных, противоречиях и недоступных инструментах |

## Требования к тексту

- Инструкции конкретные. Не «проверить внимательно», а «найти первое неверное действие и назвать его»
- Правила решения с порогами. Не «если всё плохо», а «нет критерия К1 — закрыть»
- Без общих напоминаний и повторов
- Примеры — только если они снимают неоднозначность

## Чем скил отличается от спецификации

**Скил** — про метод. Применим к любой задаче и не упоминает этот репозиторий.

**Спецификация** — про конкретную работу: что делаем здесь и сейчас, зачем и как проверяем. Лежит в `specs/`.

Если метод можно применить к десяти разным проектам — это скил. Если это описание одной задачи — спецификация.
